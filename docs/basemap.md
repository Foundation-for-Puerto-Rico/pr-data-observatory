# The base map

Every map of the observatory draws its data over a base map: streets, water, land cover and place names. This page says where that base map comes from, what each part is licensed under, what happens when it cannot load, and how to change it. Since 2026-10-23 (branch `basemap-openfreemap`, HANDOFF decision 61) one file sets it for every map: `site/js/core/basemap.js`.

## 1. Four layers, kept apart

| Layer | What it is | Today | License and credit |
|---|---|---|---|
| 1. Geographic data source | The facts on the base map: roads, buildings, water, land use, place names | **OpenStreetMap** | ODbL 1.0. Credit "© OpenStreetMap contributors" ("© colaboradores de OpenStreetMap"), linked to https://www.openstreetmap.org/copyright |
| 2. Tile provider | The service that cuts that data into vector tiles in the **OpenMapTiles** schema and serves them, with styles, fonts and icons | **OpenFreeMap** (`tiles.openfreemap.org`): Positron style on the 2D map and the WCRP maps, Liberty on the 3D view, by default; on the 2D map and the 3D view the viewer can switch to five OpenFreeMap styles, three **USGS National Map** maps (raster tiles that are their own source, not OpenStreetMap) or no base map (section 3, "The switcher" and "More base maps") | Free public instance, no key, no request limit, no SLA, as is. Credit "© OpenMapTiles" (schema: code BSD 3-Clause, design CC BY 4.0) and "OpenFreeMap" (optional, shown anyway) |
| 3. Rendering library | The code that draws the tiles in the browser | **MapLibre GL JS 4.7.1** (cdnjs, the same file in 2D and 3D). In 2D it is drawn as a layer of **Leaflet 1.9.4** through **MapLibre GL Leaflet 0.1.4** (vendored in `site/vendor/maplibre-gl-leaflet/0.1.4/`, ISC) | BSD 3-Clause; ISC; BSD 2-Clause. No credit required on the map |
| 4. Observatory data | Everything the observatory itself draws: municipios, barrios, flood zones, stops, routes, places, Economy layers | Leaflet panes (2D), MapLibre layers and deck.gl (3D) | Each layer carries its own credit line, as before |

Terrain is a fifth source, used by the 3D view only: **AWS Terrain Tiles** (Mapzen, Terrarium encoding, `s3.amazonaws.com/elevation-tiles-prod/terrarium`). Its attribution page (https://github.com/tilezen/joerd/blob/master/docs/attribution.md, read 2026-10-23) asks for "Mapzen" and a credit for each dataset; the US ones are public domain and USGS asks for "3DEP, SRTM and GMTED2010 data courtesy of the U.S. Geological Survey". The 3D credit line now reads "Terrain: Mapzen / AWS Open Data · 3DEP, SRTM and GMTED2010 data courtesy of the U.S. Geological Survey · ETOPO1: NOAA" (before: "Terrain: Mapzen / AWS Open Data", without USGS).

**Where OpenStreetMap is.** OpenStreetMap stays the geographic data source of every base map, and the source of the stops, taxi stands, routes, road graph (`roads.bin`) and place-name index (`gazetteer.json`) the build reads from Geofabrik and Overpass. What changed is only the *tile server*: the 2D map and the WCRP maps no longer ask the OpenStreetMap Foundation's raster tile server (`tile.openstreetmap.org`) for pictures. That server's usage policy (https://operations.osmfoundation.org/policies/tiles/) offers no SLA, may block heavy users without notice and points production sites to other providers. `tests/basemap.test.js` fails if that host appears anywhere in `site/`. The optional address lookup still calls `nominatim.openstreetmap.org`, only on a click (its own policy allows that).

## 3. How the pages load it

- **2D map** (`app.js`, `startBasemap`) and **WCRP page** (`wcrp.js`, `W.basemap`, used by `wcrp_social.js` and `wcrp_vuln.js`): after `performance.mark('ready')` they add `js/core/basemap.js`, which adds the MapLibre stylesheet and script (same cdnjs URLs and integrity hashes as `3d.html`, so the 3D view and the 2D map share the browser cache) and the vendored bridge, then `L.maplibreGL({ style, interactive: false, pane: 'tilePane' })`. Nothing of this is in the pages' HTML, so the first load is unchanged. `budget.py` counts these files apart, from the `deferred` list of each route in `dictionary_src/routes.json`, against `deferred_kb` (200 KB): 186.9 KB, almost all MapLibre (171 KB Brotli).
- **3D view** (`3d.html`): loads `js/core/basemap.js` with the page and reads the style URL (`Core.basemap.style('3d')`), the credits (`credits('3d')`), the terrain source and credit (`TERRAIN`, `terrainCredit()`), the plain fallback style (`FALLBACK_STYLE`) and the provider test (`isProvider`) that finds the provider's credit on its vector source. Its fallback is in section 4.
- **Stacking.** The bridge draws into Leaflet's tile pane (z-index 200); the observatory's lowest pane is `rings` (345) and every other pane is above, so the base map is always under every observatory layer. It is not interactive (`interactive: false`): every click, hover and pop-up goes to the observatory's layers exactly as before, except while the viewer has switched on the OpenStreetMap inspector (section 8).
- **Zoom.** The raster layer used to set the map's maximum zoom (19 on the 2D map, 17 on the WCRP maps). The maps now set it themselves (`maxZoom`), so deep links and the clusters behave as before. OpenFreeMap tiles stop at zoom 14 and are enlarged above it.
- **Printing.** The GL canvas keeps its drawing buffer (`preserveDrawingBuffer: true`) so it prints.
- **Credits.** The Leaflet credit box (open on a wide screen; on a phone it folds behind an "i" button, see "Credits on a phone" below) shows "© OpenStreetMap contributors · © OpenMapTiles · OpenFreeMap" (Spanish: "© colaboradores de OpenStreetMap · …") with the other layers' credits, while the base map is drawn. The 3D view's box keeps its data credits; the same base-map line, in the page's language, takes the place of the credit the provider's TileJSON puts on its vector source, so it shows once (before 2026-10-26 the box showed both, the provider's in English), and only while the base map is drawn; the terrain source adds its own line.

### The switcher: Positron, Liberty or no base map (2026-10-26, HANDOFF decision 62)

The project lead asked for both OpenFreeMap styles ("Why not both options?", 2026-10-26) and approved OpenFreeMap's terms the same day. The viewer chooses in a "Base map / Mapa base" select in the Layers panel, with a one-line description under it:

| Choice | Name (es / en) | Description | Loads |
|---|---|---|---|
| `positron` | Claro (Positron) / Light (Positron) | a light map style that keeps the data in front | the Positron style, its tiles, fonts and icons |
| `liberty` | Detallado (Liberty) / Detailed (Liberty) | streets, places, buildings and more labels | the Liberty style, its tiles, fonts and icons |
| `none` | Sin mapa base / No base map | data only, on a plain background | nothing |

- **Where.** On the 2D map it is the first row of the Reference group (Territory before navigation PR 5); on the 3D view, the first row of the 3D scene group, next to terrain and buildings, which depend on it. A control in a map corner was the other option. It was not chosen because the corners already hold the zoom buttons, the scale, the credits and (in 3D) the time bar, which are crowded at 390 px, and the Layers panel is where the menu says what is drawn. The select is in the pages' HTML, disabled until `basemap.js` wires it (`control()`); its option names and descriptions come from `OPTIONS`, and `tests/basemap.test.js` checks that the HTML and the Spanish bundles match them.
- **Defaults.** Positron on the 2D map, Liberty on the 3D view (`VIEWS`). The WCRP maps keep Positron and have no switcher.
- **Remembered.** A pick is written to the address as `bm=positron|liberty|none` and carried by the 2D→3D and 3D→2D links (since branch `view-state`, with the whole view state: `docs/view-state.md`). It is also kept in this browser (`localStorage` key `twin.basemap`, read and written in try/catch) as the viewer's default. A view opens on `bm=` from the address, else the kept default, else its own default. A link with no `bm=` (every link made before this change) keeps the defaults. `bm=` is written only after a pick or when the link had it, so a default never travels in a shared link. A pick is kept only once the map has taken it: a pick the 3D view refuses (a switch still under way, or before the view has started) or cannot load leaves the kept default as it was. The 2D map does the same since 2026-10-26 (branch `basemap-followups`, review of PR #92): it kept the pick at once, before its style had loaded; now `leaflet()` keeps it (`set(name, { keep: true })`) when the style loads, or at once for "none", and never when its style fails or another pick comes first. A style that loads is kept even if its tiles or fonts then fail (the map then goes off with its notice), as in the 3D view.
- **2D: what a switch changes.** Only the MapLibre layer in Leaflet's tile pane: the old one is hidden at once and removed when idle, and a new one is drawn with the new style. The observatory's panes, layers, pop-ups, the "layers on" chip and Undo are untouched (checked in the browser with an open pop-up). "None" removes the layer and loads nothing. The 2D map then shows the data credits only, with "Mapa base desactivado / Base map off" in front, and its full sentence as a tooltip.
- **3D: what a switch changes.** The view fetches the new style first; if the provider does not answer, the map stays as it was and a message says so. It then calls `map.setStyle(style, { diff: false, transformStyle })`. `carryStyle` (`twin3d.js`) carries every source and layer that is not the old base style's into the new one, in order:
  - layers that were under the old labels go under the new labels;
  - the rest (places, stations, WCRP pins, the planned route) stay on top;
  - after a style with no labels, `TOP_RE` decides which layers stay on top;
  - terrain and sky are carried too and set again once the style is in.
  deck.gl draws on its own canvas, and the click dispatcher is bound to layer ids, so neither changes. The WCRP pin images are given again through `styleimagemissing`. The 3D buildings and the counts on the clusters of stops need the base tiles and fonts, so they are dropped on "None" and come back with either style (`baseExtras`). The credit control is rebuilt with the new line ("Base map off" on "None").
- **Weight.** Nothing is added to the first load of the 2D map beyond the select's HTML and a few lines of `app.js`; `basemap.js` still loads after ready, and Liberty is fetched only when chosen.
- **Glossary.** "Base map" and "map style" are defined; each description under the select names the map style, which is underlined. "Positron" and "Liberty" are not added as terms: they appear only as style names inside the select, always beside their plain description.

### More base maps: three OpenFreeMap styles and three USGS maps (2026-11-13, HANDOFF decision 102)

The project lead asked for more base maps ("Add more base maps if you can. Research with ones you can add so we can have more options then add them", 2026-11-13). The switcher now offers nine choices, under two headings of the select (`GROUPS`; `<optgroup>`, its label written in the page's language by `control()`):

| Choice | Name (es / en) | Provider | What it is |
|---|---|---|---|
| `positron` | Claro (Positron) / Light (Positron) | OpenFreeMap | as before |
| `liberty` | Detallado (Liberty) / Detailed (Liberty) | OpenFreeMap | as before |
| `bright` | Colorido (Bright) / Colorful (Bright) | OpenFreeMap | roads by class, parks, water and points of interest |
| `dark` | Oscuro / Dark | OpenFreeMap | dark, few labels |
| `fiord` | Azul oscuro (Fiord) / Dark blue (Fiord) | OpenFreeMap | dark blue, streets and labels in soft tones |
| `imagery` | Imágenes aéreas / Aerial imagery | USGS National Map, `USGSImageryOnly` | orthoimagery, no labels |
| `topo` | Topográfico / Topographic | USGS National Map, `USGSTopo` | contours, shaded relief, water, roads, names |
| `relief` | Relieve sombreado / Shaded relief | USGS National Map, `USGSShadedReliefOnly` | 3DEP shaded relief only |
| `none` | Sin mapa base / No base map | | as before, last and outside the headings |

**The three OpenFreeMap styles** are the provider's other public styles (`tiles.openfreemap.org/styles/bright`, `/dark`, `/fiord`, checked 2026-11-13). They read the same `openmaptiles` vector source, fonts and icons as Positron and Liberty, under the terms the project lead approved for decision 62, so they add no source, no license and no new credit. The map inspector, the 3D buildings and the stop counts work on them as on Liberty.

**The USGS maps** are raster tiles of The National Map (`basemap.nationalmap.gov/arcgis/rest/services/<service>/MapServer/tile/{z}/{y}/{x}`, 256 px, no key).
- **Terms** (USGS FAQ, read 2026-11-13: https://www.usgs.gov/faqs/what-are-terms-uselicensing-map-services-and-data-national-map): the map services and data are free to use with no use restrictions; credit is requested, "Map services and data available from U.S. Geological Survey, National Geospatial Program". The map's credit line is "Base map: U.S. Geological Survey, National Geospatial Program" ("Mapa base: Servicio Geológico de EE. UU. (USGS), Programa Geoespacial Nacional"), linked to https://apps.nationalmap.gov/services/; the aerial imagery adds "Orthoimagery: USDA, USGS", the service's own copyright line. `SOURCES.usgs` and `SOURCES.ortho`; source card `usgs_basemaps`.
- **Not offered: USGS Imagery Topo** (imagery with labels). The USGS retires it on 2026-11-16 (https://www.usgs.gov/the-national-map-data-delivery/news/imagery-topo-base-map-retirement). `USGSHydroCached` is a transparent overlay of streams, not a base map.
- **Coverage over Puerto Rico** (checked 2026-11-13, about 40 tiles per zoom over the island, Vieques and Culebra): every zoom from 6 to 16 answers for the three services; none answers at 17. `USGSImageryOnly` answers 404 at zooms 9 and 10. The style is built in `rasterStyle()`: a source `usgs` to zoom 16 (MapLibre enlarges above), and for the imagery a second source `usgs-low` (to zoom 8, enlarged) drawn under `usgs`, which starts at 11. The service's own `export` gives the same enlarged picture at 9 and 10. So no tile request answers 404 and the tile rules (section 4) watch real failures only. The imagery is sharp from zoom 11 (Old San Juan checked at 16) and coarse at the island view.
- **What the tiles hold.** They are pictures: no OpenStreetMap data, no features. So the **map inspector** is disabled on them, with the note "El inspector solo lee los mapas base de OpenStreetMap: elija uno de ellos para usarlo." (`Core.basemap.inspectable`), in 2D and 3D; and the **3D buildings** (OpenStreetMap's building tiles, and the Overture buildings that fill their gaps) are not drawn over them, as with no base map. The stop counts and the view's own labels need fonts: a USGS style carries OpenFreeMap's (`GLYPHS`), which no request asks for unless a label is drawn.
- **Known looks of the tiles.** Offshore, the imagery has a white strip where the photographs end (seen at zoom 11 and 12 off San Juan). The shaded relief's sea is white in some tiles and transparent in others, so its background is that white (`#fdfdfd`). The dark styles show the observatory's dark-blue municipal lines with less contrast than a light style.
- **3D.** A USGS style is an object, not a URL: `switchBasemap` applies it without fetching (`typeof st === 'string'`); its tiles are watched by the same rules. The credits are those of the style going in (`BM.next` during a switch, `bmCredits()`): the USGS source carries its credit line, which the credit listener finds with `isProvider` (host `nationalmap.gov`). `creditOn` is reset at each switch, since the provider's source id changes (`openmaptiles` ↔ `usgs`). `vectorSourceId()` now returns only the provider's vector source: before, after a switch to "No base map" it found the view's own PMTiles of the buildings OpenStreetMap lacks, added an empty `buildings-3d` on it and kept those buildings alone over a plain background.
- **Addresses.** `bm=bright|dark|fiord|imagery|topo|relief` are read and written like the others. The 2D map reads `bm=` before `basemap.js` loads, from its own list (`BM_NAMES` in `app.js`); it listed only the first three names, so a link with `bm=topo` opened on the kept default. A test keeps both lists equal.
- **Credits on a phone** fold once a base map's credit is in the box (`CREDITED`): OpenStreetMap's, or the USGS line (before, only "OpenStreetMap", so a USGS map would have waited the full 20 s).
- **Weight** (`budget.py` on LF copies, main b533f01 then this branch): map scripts 189.0 → 189.4 of 250 KB; libraries after ready (MapLibre, the bridge and `basemap.js`) 193.8 → 196.0 of 200 KB on the map and 192.6 → 194.8 on the WCRP page; 3D scripts 323.9 → 326.7 of 700 KB. A USGS map loads only its tiles; MapLibre is the same.
- **Considered and not added.** Esri World Imagery and the other ArcGIS Online basemaps: an Esri staff answer on the Esri Community forum says the keyless service needs an ArcGIS Online or Enterprise license and is not for commercial use, so it stays out until Compliance reads Esri's terms. Sentinel-2 cloudless (EOX): its recent years are under CC BY-NC-SA 4.0, a non-commercial and share-alike license for Compliance to weigh. OpenTopoMap, CARTO and NASA GIBS: not reviewed in depth; the USGS Topo and OpenFreeMap's styles cover the same needs with no key and no quota question. Puerto Rico's own orthophotos (Junta de Planificación, CRIM): no keyless tile service found; USDA NRCS lists 2010-2012 30 cm orthophotos of Puerto Rico as image services (not tested), a possible later layer.

## 4. Loading and failure

- **Loading:** the map's container has `data-basemap="loading"` and the credit box starts with a small spinner and "Cargando el mapa base… / Loading the base map…", removed when the style has loaded.
- **The base map goes off**, for the rest of the page view, when:
  - WebGL is unavailable (probed before anything is downloaded; also a lost WebGL context, or MapLibre failing to create one);
  - the libraries do not load;
  - the style does not load (an error of the style, its fonts or its icons before MapLibre's `load` event, or 30 s without that event);
  - eight tile errors in a row, with no tile arriving in between;
  - or, since 2026-10-26, the map goes idle and every tile it asked for since it was last idle failed, at least two of them (since branch `basemap-followups`: one tile that fails alone is not an outage). A small map asks for fewer than eight: the WCRP vulnerability map needs about 6 at zoom 9 and, with every tile failing, used to keep an empty background with full credits and no notice.
- **Then:** the GL layer is hidden at once and removed when MapLibre has no request in flight (so it logs no AbortError); its credit line goes with it; `data-basemap="off"`; the map keeps every layer over its plain light background (`#d9e6ee` on the 2D map, `#eef3f6` on the WCRP maps) with the municipio or barrio outlines; the credit box starts with "Mapa base no disponible / Base map unavailable" (its full sentence as a tooltip), and the 2D map also shows its usual non-blocking message: "Mapa base no disponible: su proveedor no responde. Los datos se muestran sobre un fondo liso." (or, without WebGL, "…este navegador no puede dibujarlo (WebGL está desactivado o no es compatible)…").
- **The notice** (2026-10-26) is the base map's own: a small box over the map (`Core.basemap.notice`, with a × and gone after 9 s), plus the note at the start of the credits. It no longer uses the page's message bar, so it never withdraws an Undo waiting there. The 3D view uses the same notice for its fallback and for a switch that fails.
- **3D credits** (2026-10-26): the base map is credited once, by our line in the page's language on the provider's own source (PR #94); it leaves with the base map. The credit box was always open until 2026-10-29; it is now open on a wide screen and folds on a phone ("Credits on a phone" below). It ends before the map buttons, its text is 9 px on a phone, and it never takes a click meant for the map: the box lets clicks through (`pointer-events: none`) and only its links answer, so a cluster of stops under the credits at 390 px still zooms in (`tests/browser/cluster_clicks.js`). When the base map is off or unavailable, the box adds "Mapa base desactivado / Base map off" or "Mapa base no disponible / Base map unavailable".
- **Credits on a phone** (the project lead, 2026-10-29, HANDOFF decision 65; it replaces the "always open" rule of decision 62 (f)). On a screen under 700 px (`PHONE` in `basemap.js`), the 2D map, both WCRP maps and the 3D view put a round "i" button (32 px, a 44 x 44 px target) in the credits' corner, below the box (`Core.basemap.fold`). The box shows the full credits when the map opens; it folds 5 s after the OpenStreetMap credit is in it (20 s at most when the base map never comes), or at the first touch, click or wheel on the map. The button opens and closes it again with a tap, Enter or Space; its name is "Créditos del mapa" / "Map credits" and it says whether the box is open (`aria-expanded`, `aria-controls`). Wider screens keep the box open and show no button. Printing shows the credits. This follows the OpenStreetMap Foundation's attribution guidelines (https://osmfoundation.org/wiki/Licence/Attribution_Guidelines, read 2026-10-29: the attribution may fold "automatically on map interaction" or "automatically after five seconds", and must stay findable "from an '(i)' button in the corner of the map") and is like MapLibre's compact credits, which show at first and fold at the first drag (with no timer); the 5 s fold comes from the OSMF guideline. The box is not folded before it has been shown: a box folded from the very first frame would not meet those guidelines. The 2D and WCRP maps get the button when `basemap.js` loads, after ready; until then their credits are open. `tests/browser/usability.js` checks it in both languages at 1400, 390 and 320 px.
- **2D credits after a failure** (review of PR #92): the bridge adds its layer's credits again when its map loads (it removes and adds them on `load`), which can come after the base map went off, while the layer waits to be removed. With only the fonts blocked, the credits then stayed. They are taken off again on that `load`.
- **Stop counts after a switch** (review of PR #92): the counts on the clusters of stops, dropped with no base map, come back with their clusters' visibility, so stops switched off meanwhile do not leave counts drawn alone (`tests/browser/basemap_switch.js`).
- **After a failure** the switcher stays: a new pick tries afresh (2D), or (3D) is fetched first and refused with a message when the provider still does not answer, the map kept as it was; a pick that goes in replaces the base style, shows the buildings again as their switch says, and the failure rules then watch the new style. A pick that goes in (a style that loads, or "none") also takes away a notice still shown over the map (`Core.basemap.clearNotice`): a "could not be loaded" stayed up to 9 s over a working map (review of PR #92). In 3D it also stops a pending check of the clock rule and resets `BM.why`.
- **Never** a fallback to `tile.openstreetmap.org`.
- **The 3D view** (`site/js/twin3d.js`) needs a style to start, so it has its own fallback, with the same two rules as above (30 s, eight tile errors in a row):
  - **The style fails before start.** Any error that is not about a source or a tile (it has no `sourceId` and no `tile`) before the view has started is the style, its sprite or its fonts. When the provider is down, blocked or unreachable, the browser reports only "Failed to fetch", with no URL, so the error text alone cannot name the provider. The view switches to the plain style (`FALLBACK_STYLE`, background `#dfeef7`) and starts on it.
  - **No style after 30 s** (the provider never answers): the plain style too. A style that has loaded, with its tiles still coming, starts the view at 30 s with the base map.
  - **The tiles fail after the style has loaded**: a base-map source that does not load (its TileJSON), or eight tile errors in a row from one of its sources with no tile arriving in between, before or after start, hides the base map's layers (and the view's buildings, drawn from the same tiles). The style's own plain background stays.
  - **Every base-map tile failing** (review of PR #92): the default view asks for only about 4 tiles before start, under the run of eight, and the view is seldom idle (its sources keep asking for the failed tiles), so the 2D maps' idle rule runs on a clock (`Core.basemap.tileWatch`, used by `twin3d.js`): a window opens with a failed base-map tile; 6 s later a source counts as down when two or more of its tiles failed in the window, none arrived, and none is still loading (`map.isSourceLoaded`). While a source has tiles in flight the window stays open and is looked at again each second, so a slow provider is not taken for a dead one. Before branch `basemap-followups` one failed tile was enough and tiles in flight counted as failed: in a synthetic test (the first tile failed, the others held 7 s) the base map hid at 6.1 s and stayed off, with its notice, over tiles that then arrived (`tests/browser/basemap_switch.js`, case 2, on `main` at e843616).
  - **When the tiles come back** (branch `basemap-followups`): after a tile rule (the clock or a run of eight), each source found down keeps loading under one invisible layer (`bm-watch-<source>`; a hidden layer's source asks for nothing and drops its tiles in flight). When one of its tiles arrives (a slow provider, or one back after an outage, seen after a pan), the base map comes back: its layers with the visibility each had, the buildings as their switch says, its credits, `BM.off` false and `BM.why` null, and the notice goes. This happens once per style: with only the fonts failing, the tiles arrive under the invisible layer and fail again with the labels, so a second failure on the same style stays (checked with the fonts blocked: the base map came back once within the first second, then was hidden for good about 2 s after loading). A source whose TileJSON does not load is not watched. A switch removes the invisible layers (they are never carried into the new style).
  - **Then**, in every case: the terrain, the municipio outlines, the route lines and the other data layers draw as usual, the page reaches `ready`, the base map's own notice "No se pudo cargar el mapa base. ## 5. Switching providers or styles

Everything is in `site/js/core/basemap.js`:
1. Add the provider to `PROVIDERS`: its `styles` (name → style URL), `credits` (ids in `SOURCES`, in the order the map shows them), `host` (a pattern for its URLs, used to tell its errors from the observatory's), and `key: null`.
2. Add any new source to `SOURCES`, with `role`, `name`, `url`, `licence`, `licence_url` and `credit: { en, es }`.
3. Add or change a style in `OPTIONS` (provider, style, es/en name and description; the select's options in `index.html` and `3d.html` and their Spanish follow) and point `VIEWS['2d']` or `VIEWS['3d']` at the default (`{ provider, style }`).
4. Update the source cards (`dictionary_src/sources.json` and `es/sources.json`), this page, and run `node --test tests/basemap.test.js` and `python budget.py`.

**A provider that needs a key.** Prefer providers without one: a key in a web page is public. If one is ever needed, give the provider `key: { name: '<name>', param: '<query parameter>' }`. The key goes in `site/js/basemap.local.js` (listed in `.gitignore`, never committed) as `window.BASEMAP_LOCAL = { <name>: '<key>' };`. `basemap.js` loads that file before asking for the style on the 2D maps; the 3D view needs a `<script src="js/basemap.local.js">` before `js/core/basemap.js` in `3d.html`. A deployment that needs the key adds the file at publish time (for example from a repository secret in the Pages workflow), restricted by the provider to the site's domain.

## 6. Long term: self-hosted PMTiles for Puerto Rico

If OpenFreeMap ever becomes unreliable, the independent option is to build Puerto Rico's own vector tiles (a Protomaps or OpenMapTiles extract of the island as one PMTiles file, read by MapLibre with the `pmtiles` protocol) and publish them with the site on GitHub Pages, with a style, fonts and sprites hosted beside them. It needs a build step and its file size has not been measured. With `basemap.js`, it is a new provider entry; the pages would not change.

## 8. The OpenStreetMap feature inspector (2026-10-27, branch `osm-inspector`, HANDOFF decision 64)

The project lead asked that viewers can interact with the OpenStreetMap layer: inspect what a street or place on the base map is, and go to its OpenStreetMap page. The 2D map and the 3D view have an **"Inspeccionar mapa / Inspect map"** toggle under the base-map switcher (first group of the Layers tab). It is a button with `aria-pressed`, reached and used with the keyboard, and it carries `data-no-glossary`.

**What it does.** While it is on, a click or tap on the map asks MapLibre for the base map's features under the pointer (`queryRenderedFeatures` over a 7 × 7 px box; in 2D on the MapLibre map of the Leaflet bridge, `getMaplibreMap()`). It keeps only the features of the provider's vector source (`isProvider` on the style's source URL), never an observatory layer, and shows a small pop-up for the topmost one it may show:
- its **kind** in plain words, in Spanish or English ("Carretera primaria / Primary road", "Lugar de culto / Place of worship", "Vecindario / Neighborhood"). About 200 OpenMapTiles classes and subclasses have a name; the rest get a generic kind for their layer. A bridge adds "(bridge)".
- its **name** as OpenStreetMap has it (`name`, shown as is, `translate="no"`), and a road's **number** ("Número de carretera: PR-1", from `ref`). A motorway junction (`transportation_name`, subclass `junction`, a node) is a "Salida de autopista / Motorway exit" with its "Número de salida / Exit number". A road's name and number are in the label layer (`transportation_name`), which is drawn only along parts of the line. A click on the line borrows them from a label line only when it is the same road at the click (the matching rule below).
- the **OSM element** ("Elemento de OSM: vía 22223468", a glossary term) and the link **"Ver en OpenStreetMap / View on OpenStreetMap"** to `https://www.openstreetmap.org/{node|way|relation}/{id}`, in a new tab.
- the credit **"© colaboradores de OpenStreetMap · ODbL"**, linked to https://www.openstreetmap.org/copyright (the map's own credit line, `SOURCES.osm.credit`). OpenStreetMap's data are under the Open Database License 1.0 (https://opendatacommons.org/licenses/odbl/1-0/). Showing a feature's name and linking to its page uses the map's data under the same credit; nothing is extracted or republished.

A bar over the map says the mode is on, with a "Salir / Leave" button. **Esc** also leaves, and the focus goes back to the toggle when it can be seen. Outside the mode nothing of this runs: the observatory's own clicks (municipalities, flood zones, stops, cards) behave exactly as before. While it is on, the inspector takes the clicks on the map first:
- In 2D it catches only clicks on Leaflet's map pane (the base map, the observatory's shapes and markers), before Leaflet's layers; a drag is not a click. Everything else in the map's container keeps working: the "layers on" chip and its list, the message and its Undo, legends, notices, zoom and credits (review of PR #99: the first version caught every click in the container). No key is caught.
- In 3D the view's click handler steps aside while the container has `data-inspect="on"`.
- On a phone, turning it on closes the panel so the map can be seen, and the focus moves to the bar's "Salir / Leave" button (the toggle is in the closed panel, which is inert). Leaving then puts the focus on the menu button that opens the panel.
- **A switch of base-map style ends the mode**, in 2D and 3D alike: the viewer turns it on again on the new style.

**When it is off.** The toggle is disabled, with a one-line reason under it, while the base map loads ("Disponible cuando el mapa base haya cargado"), when it is switched off ("Active un mapa base para inspeccionarlo") and when it is unavailable, with no WebGL or the provider down ("El mapa base no está disponible…"). A base map that goes off or is switched to "none" also ends the mode. The 3D view's no-WebGL fallback is unchanged: the view stops before the toggle is wired, and the toggle stays disabled.

**Not in the address.** The mode is not part of the view state (`docs/view-state.md`). A shared link that opened in inspect mode would take the recipient's clicks away from the data layers without their knowing.

### The OpenStreetMap ID: what the tiles carry (checked 2026-10-27)

OpenFreeMap builds its tiles with **Planetiler** and the **OpenMapTiles profile** (its README, https://github.com/hyperknot/openfreemap: "The `tilegen` script downloads a full planet OSM extract and runs it through Planetiler"; its TileJSON, https://tiles.openfreemap.org/planet, names OpenMapTiles 3.16). Planetiler writes each feature's vector-tile ID as **OSM ID × 10 + a type code: 1 node, 2 way, 3 relation, 0 for any other source**:
- `PlanetilerConfig`, argument `feature_source_id_multiplier`, default 10: "(featureId * thisValue) + sourceId where sourceId is 1 for OSM nodes, 2 for ways, 3 for relations, and 0 for other sources" (https://github.com/onthegomap/planetiler/blob/main/planetiler-core/src/main/java/com/onthegomap/planetiler/config/PlanetilerConfig.java);
- `OsmElement.vectorTileFeatureId`: node 1, way 2, relation 3, other 0 (https://github.com/onthegomap/planetiler/blob/main/planetiler-core/src/main/java/com/onthegomap/planetiler/reader/osm/OsmElement.java);
- features **merged** in post-processing (road lines joined at low zoom, label lines, land-cover polygons) get `FeatureMerge.makeMergedId`, which sets the last digit to 0 (https://github.com/onthegomap/planetiler/blob/main/planetiler-core/src/main/java/com/onthegomap/planetiler/FeatureMerge.java). This needs **Planetiler 0.10.0 or later**: the change is PR #1397, "When merging features, assign IDs ending in 0 to the result" (https://github.com/onthegomap/planetiler/pull/1397, merged 2025-11-26, released in v0.10.0 on 2026-02-11). Before it, a merged feature kept the ID of one of its parts, with its type code. OpenFreeMap's tiles of 2026-10-25 agree with the new rule (24 merged roads ending in 0). If a provider ever serves tiles from an older Planetiler, a merged road would link to one of the ways it joins;
- the layers and their attributes: https://openmaptiles.org/schema/ and https://github.com/openmaptiles/planetiler-openmaptiles.

**Checked on the tiles themselves.** Tile 14/5183/7336 (Old San Juan) of OpenFreeMap's build of 2026-10-25, decoded:

| Layer | Features | Last digit of the IDs |
|---|---|---|
| `poi` | 1,196 | 1, 2 or 3 |
| `place` | 19 | 1 or 3 |
| `transportation` | 219 | 194 end in 2, 1 in 3, 24 in 0 (merged) |
| `transportation_name` | 94 | 47 end in 2, 47 in 0 |
| `building` | 40 | 27 end in 0 |
| `housenumber` | 189 | (never read) |
| `water` | 6 | 1 ocean ending in 0 (coastline data); 5 ending in 2, the lakes' and pools' ways (each also in an `id` attribute) |

Seven decoded IDs were looked up on `api.openstreetmap.org` and matched their name and tags: node 53200527 (San Juan, city), node 1900492512 (Cataño), node 4304974917 (Viejo San Juan), way 22223468 (Calle Sur), way 22224778 (Callejón del Gambaro), way 295319636 (a nursing home) and way 113347943 (a pier). In the browser test, way 22228663 is Calle de la Cruz. Two water IDs were checked too (review of PR #99): way 421337002 (`natural=water`) and way 295180942 (a pool). The first version of this section said water IDs ended in 0 and 4; that was a decoding error of ours (a feature attribute named `id` overwrote the feature ID). MapLibre GL JS 4.7.1 keeps the tile IDs on the features it returns (`feature.id`).

**The rule** (`osmRef` in `site/js/core/osminspect.js`):
- a link only for a safe positive integer ending in 1, 2 or 3, on a layer whose features come from OpenStreetMap elements: `poi`, `place`, `transportation`, `transportation_name`, `aerodrome_label`, `mountain_peak`, `water_name`, `waterway`, `water`, `aeroway`, `park`, `landuse`, `landcover`;
- an ID ending in 0 gets no link and the note "Sin enlace a este nivel de zoom: … Acerque el mapa" (merged). In `water` it is the ocean, drawn from coastline data, and the note says so ("Sin enlace: esta área de agua se dibuja con datos de la costa…"). A feature with no usable ID says that the tiles carry none.

**Matching a road's line and its label** (`sameAlong`; review of PR #99). A merged label line (ID ending 0) may take the ID of the road's own line, and a road's line may take the name and number of its label line, only when both are the same road at the click. The first version took the nearest line of the same class within 8 px; near a crossing that was the cross street (4 of 101 points in Old San Juan: "Calle de San Francisco" got way 22230974, Calle de O'Donnell). Now a candidate must:
- pass within 2.5 px of the point of the clicked line nearest the click;
- run at a bearing within 12° of it there;
- have every vertex within 40 px of that point lie within 3 px of the clicked line (a ramp that leaves the road fails);
- be the only road that does: when two distinct roads fit, neither lends;
- for an ID, not be a ramp (`ramp`).

Otherwise nothing is borrowed: a label shows its name with the "zoom in" note and no link, and a line shows its kind and its own link with no name. A name is never shown with another object's link.

**No ID is ever guessed.**

### Privacy

The observatory's standing rules: no personal data on the site; sensitive places are counted, never drawn or named (`docs/places-privacy.md`). The base map's labels are drawn by the provider's style, outside the observatory's control. The inspector adds nothing to them for anything sensitive:
- **Never:** anything from the `housenumber` layer, and **no address** of any kind. Neither style draws house numbers, and the inspector never reads that layer.
- **Buildings:** passed over. The OpenMapTiles `building` layer carries no name or use (only heights and color), and most buildings are homes. So the inspector never describes a building; the click goes to the next feature down (a point of interest, the street, the land use).
- **Swimming pools** (`water` and `poi`): passed over; most are at homes.
- **Sensitive kinds: a generic kind only, with no name and no link**, and the note "Nombre y enlace omitidos: el observatorio no identifica lugares de este tipo":

| Generic kind shown | OpenMapTiles values | Why |
|---|---|---|
| Atención de salud / Health care | `clinic`, `doctors`, `dentist`, `nursing_home`; office `physician`, `therapist`, `psychotherapist`; `counselling`, `rehabilitation`, `hospice`, `healthcare`, `alternative` | being there says something about a person's health; clinics and offices are often named after one doctor; a nursing home is where people live |
| Servicios sociales / Social services | `social_facility`, `shelter`, `refugee_site`, `group_home`, `assisted_living`, `social_centre`, `women_shelter` | shelters, including domestic-violence and homeless shelters, must not be found from a map. The schema cannot tell a bus shelter from a refuge, so every `shelter` is treated alike |
| Cuido de niños o preescolar / Child care or preschool | `kindergarten`, `childcare` (points of interest, and land-use areas of those classes) | many are run in a home |
| Alojamiento / Lodging | `guest_house`, `bed_and_breakfast`, `chalet`, `apartment`, `holiday_home` | often a private home (short-term rentals are a pending decision: HANDOFF, decision 5) |
| Oficina / Office | every `office` value except public bodies and institutions: government, diplomatic, quango, educational institution, university, research, utilities, harbor master, NGO, association, foundation, charity, political party, religion, union, newspaper, telecommunication, cooperative | a lawyer's, accountant's or consultant's office is often one person, named after them |
| Comercio / Business | `erotic`, `massage`, `brothel`, `stripclub`, `swingerclub`, `love_hotel` | sexual life |
| Lugar poblado / Populated place | `place=isolated_dwelling`, `place=farm` | a single home |

- **Shown with name and link:** hospitals (public landmarks), pharmacies, police and fire stations, prisons and courthouses (public institutions), schools and universities, hotels, motels and hostels (businesses), and **places of worship**. Places of worship were weighed. Religion is a special category of personal data, but a church, mosque or synagogue is an organization's public building, already named on the base map, and the inspector says nothing about any person. Leaving them out would hide a large share of Puerto Rico's landmarks. Political-party and union offices follow the same reasoning.
- **Roads** keep their names, service roads and tracks included: a street name is public. A private driveway named after a family would show; if one is found, add `service` roads with no `ref` to the rule.
- **Tests:** `tests/osminspect.test.js` checks each sensitive value (no name, no link, the note), the public ones, and that `housenumber` and `building` are never described. `tests/browser/osm_inspect.js` clicks a house number from the tiles and a 12 × 12 grid over the map; none is described as a house number or a building.
