# Language layer: Spanish first (conventions and style guide)

The observatory speaks Spanish and English. Spanish is the first language: it is what a visitor gets when the browser lists Spanish (or nothing the observatory knows), and the
Spanish quality bar is the same as the English one. This file is the rulebook for code and for the Spanish text.

## How it works

- **English is the source.** The code keeps its English strings. Each user-visible English string is its own key. English output must stay exactly what it was.
- **Spanish lives in `i18n_src/es/<scope>.json`**: `{ "English text": "Texto en español" }`. `python i18n.py` merges the scopes of each page (`i18n_src/pages.json`) into
  `site/i18n/es.<page>.js`, which `site/js/i18n.js` loads before the page scripts run. English loads no bundle.
- **Parts of a page that load on first use have their own bundle.** The map's Scenarios and Study areas views, the other workbench views (`workbench`), the land-use analysis, the barrio shading, the public facilities, the texts of the help buttons (`help`) the Spanish names of the Catalog's entries (`catalog`) and the text of the About tab (`about`, 2026-10-21) are `modules` of the map in `pages.json`; the 3D view's public facilities (`facilities`, the same scope, with `core/facilities.js` and `facilities3d.js`) are a module of the page `threed` (2026-10-19); the OpenStreetMap inspector (`osminspect`, with `core/osminspect.js`) is a module of both `map` and `threed` (2026-10-27), and its toggle's six strings are a page scope of both (`osmtoggle`), drawn before the module loads; the WCRP page's vulnerability map (`vuln`, scope `wcrp_vuln`) is a module of the page `wcrp`, whose Social Capital map is part of the page bundle (2026-10-19).
  Each becomes `site/i18n/es.map.<module>.js` (for example `es.map.scenarios.js`), and the module's loader waits for `I18N.load('<module>')` along with its scripts before it renders. So their Spanish stays out of `es.map.js`, which every visitor downloads.
- **Language choice:** `?lang=es|en` in the address (it is also kept for the browser session, so the other pages open in the same language), else the choice saved with the ES / EN switch in the top bar, else the browser (any Spanish in its language list: es; only English: en), else Spanish.
  The switch reloads the page with `?lang=`; the map's view lives in the URL hash, so it survives. `<html lang>` follows the choice.
- **Dictionary summaries** (the `plain` field of each data dictionary entry) are the one exception to "keyed by the English text": they live in `i18n_src/dictionary_plain.json`,
  keyed by entry id, as `{ "en": the English plain it translates, "es": "Spanish" }`. `python dictionary.py` copies `es` into `site/data/dictionary.json` as `plain_es` only while `en`
  still equals the entry's `plain`; when the English changes, the page falls back to English until the Spanish is updated. The file is not a page scope (it is not in `i18n_src/es/`), so no bundle carries it.
- **Checks:** `python i18n.py --check` (the build runs it) fails when a script asks for a key that has no Spanish, when a Spanish text loses a `{placeholder}` or an HTML tag of its English key,
  or when two scopes translate one key differently. It warns for each dictionary entry with no Spanish summary, or whose summary translates an older English text. `python i18n.py --keys PAGE` lists what a page still lacks. In the browser, `I18N.audit()` lists static text that has no Spanish and
  `I18N.missed` lists the keys T() could not find (add `?lang=es` and open the console).
- **Names of dictionary entries** (the Catalog tab of the map) are data, and most have no Spanish yet. The Catalog shows the Spanish name when there is one and the English name, marked `lang="en"`, when there is none, and checks with `I18N.has(name)` first, so the names that have no Spanish are not listed in `I18N.missed`. The Spanish of names that are not series labels lives in `i18n_src/es/catalog.json`, a module of the map with no script of its own that loads with the index (`I18N.load('catalog')`). Their file is a `data_labels` entry with `"required": false`: the check does not ask for Spanish for every name, but counts the names as used.

## Rules for code

1. **Wrap at the place the text reaches the screen**, never an identifier, CSS class, selector, URL, data key, object key used for lookup, or a number. If a literal is both a label and a lookup key,
   separate the two and wrap only the label.
2. **`T('text')`** returns plain text. When it goes into HTML, escape the result once: `esc(T('Tourism places'))`. Do not escape the pieces and the whole.
3. **Placeholders, not concatenation.** Word order differs between languages: `T('{n} of {m} places', { n: fmt(a), m: fmt(b) })`, never `fmt(a) + ' of ' + fmt(b) + ' places'`.
   Placeholder names are lowercase words; the Spanish text must keep every placeholder.
4. **Plurals:** `Tn(n, '{n} place', '{n} places')` (English one, English other). The Spanish entry is an array `["{n} lugar", "{n} lugares"]`, keyed by the English "one" form.
5. **Markup inside a sentence:** `Th('<b>{n}</b> places in a flood zone', { n: fmt(x) })` returns HTML. Values are escaped automatically; to insert HTML you already built, wrap it in `I18N.raw(html)`.
   The Spanish text must have the same tags and attributes in the same order.
6. **Static HTML stays English in the file.** `I18N.apply()` (called by an inline script on each page, and once more on `DOMContentLoaded`) replaces text nodes, and the attributes
   `title`, `aria-label`, `placeholder`, `alt`, `data-ask` and `aria-description`, using the exact text as the key. A sentence that mixes text with `<a> <b> <i> <em> <strong> <code> <kbd> <abbr> <u> <mark> <sub> <sup> <br>`
   is translated as one unit, keyed by its `innerHTML` with whitespace collapsed. Opt out with `translate="no"`, `data-t="skip"`; force a unit with `data-t="html"`, or per-node with `data-t="text"`.
   Icon ligatures (`.ms-icon`) are never translated.
7. **HTML built by scripts** uses T / Tn / Th at the moment it is built. After inserting static English markup with `innerHTML`, call `I18N.apply(container)`.
8. **Numbers, dates, lists:** `fmt(n, d)` (common.js, locale-aware), `I18N.date(d, opts)`, `I18N.list(items)`. Never write `'en-US'`. Spanish numbers in Puerto Rico use the US form (1,234.5).
9. **Data-driven labels** (series labels and groups, place types, units, statuses read from JSON or built by Python) reach the screen as `T(label)`. List their file and path under `data_labels` in
   `i18n_src/pages.json` so the build checks that each has Spanish. Long definitions and source notes stay English for now (see "What is not translated").
10. **Registry names** (`dictionary_src/domains.json`) carry `{ es, en }`. Use `I18N.name(domain)` / `I18N.text(domain.description)`; never hard-code a domain name.
11. **Never translate** proper names and data values: Foundation for Puerto Rico, FEMA, ATI, Overture Maps, municipality and barrio names, street names, CSV, URL, ACS and similar acronyms
    (spell out the Spanish name beside the acronym when it first appears in a text). List unavoidable same-in-both entries in `i18n_src/keep.json`.
12. After changing a string, bump the `?v=` of `js/i18n.js` in the page (it is reused for the bundle), so visitors do not keep the old Spanish.
13. **Shared modules** (`site/js/core/*.js`) use the same `T`, `Tn` and `Th` through `Core.text` (plain English when there is no page, which is how the Node tests run them). List each core file a page loads under that page's `scripts` in `i18n_src/pages.json`, so the tool reads its strings and the page's bundle has them. The sentences of `reliability.js` (hatching, italics, cautions) sit in their own scope, `reliability`, which only the map and the Housing page load.
14. **An English text that is translated later, where it is shown** (a label stored in a data structure and passed through `T()` by the code that draws it) is written `TK('text')` where it is defined: the tool reads it like `T()` and the page does not translate it at that moment. `data_labels` entries in `pages.json` can carry `prefixes` for labels a script composes from a file's text ("Residents: " + the label of an exposure family); the exposure labels' Spanish is derived from the exposure file itself (`python exposure.py --labels`) and a test guards against drift.
15. **A module that loads on first use** gets an entry under its page's `modules` in `pages.json`: its `scopes` and its `scripts` (list the scripts there, not in the page's `scripts`). Its loader calls `I18N.load('<module>')` and renders only once both the scripts and that promise are done. A script already on the page is not loaded again.
   - **What goes in its bundle:** the module's scopes, plus every key its scripts ask for that another module's scope translates (the study areas take the contact-details strings of `core/scenario.js` from the `scenarios` scope). Anything already in the page bundle is left out.
   - **What the check demands:** `i18n.py --check` checks each module's scripts against the page bundle plus that module's bundle only, as the browser has them when the module renders. It also checks the page's own scripts against the page bundle only, so a string that the page draws before the module loads (a tab name, "Loading the scenarios…") must sit in a page scope. A module that no script loads with `I18N.load()`, or an `I18N.load()` for a module the page does not have, is an error.
   - **What the check cannot see:** static text in the page's HTML. Keep a module scope to the module's own strings.
   - **Text of a page scope that only a module shows** can leave the page bundle too (2026-10-21, to make room on the WCRP page and the map), in three ways. Each key still lives in its scope's file; only the bundle it is built into changes.
     - **Data labels given to a module:** a `data_labels` entry with `"modules": {"<page>": "<module>"}` puts its labels, on that page, in that module's bundle. The check looks for their Spanish in the page bundle plus that module's bundle. A label that the page's own scripts also ask for stays in the page bundle. The WCRP page's RVI input labels (`wcrp_rvi_barrio.json`, `method.*`) and the landslide notes (`landslide_barrio.json`) load with `vuln`, its vulnerability map, which is the only part of the page that shows them. On the map, the labels of the terrain and climate groups (`heat_*`, `vegetation_*`, `night_heat_*`, `climb_series.json`) load with the module `econ_terrain`, which `economy.js` (`ecLoad`) asks for alongside the Economy tab's data (2026-11-04, to make room under the map's 250 KB); without it the names show in English.
     - **Static text of an element a module translates:** a module's `"html": ["<element id>"]` sends the text shown only inside that element into the module's bundle. "Only" means the whole text of a node, an attribute or an element (`i18n.py`, `whole_in`), and not shown elsewhere in the page or asked for by its scripts. The module's loader then calls `I18N.apply(element)` once `I18N.load()` is done. Until then the element waits unseen, so English never flashes. The map's About tab (`about`, no script of its own) works this way: it has `data-t-wait` (`twin.css` hides its content) and `aria-hidden` (the glossary leaves it alone), and `loadAboutText()` in `app.js` removes both once the tab is translated, then asks the glossary to read it. A sentence with a `<span class="snap">` is translated with that span empty, as written in the page, and refilled after.
     - **Picked scopes:** a page's `"pick": ["<scope>"]` takes from a scope it shares with other pages only the keys its scripts ask for (`T`, `Tn`, `Th`, `TK`), its HTML shows or its own data labels need. The WCRP page picks `facilities`, whose layer texts belong to `core/facilities.js`, a script the page does not load. Pick only a scope whose keys the page's scripts name: a key reached only through `T(variable)`, with no `TK()` and no data label, would be left out and would show in `I18N.missed`.

## Spanish style guide

- **Voice:** clear, warm and plain, for Puerto Rican readers (the same plain-language rules as English: short sentences, active voice, concrete words). Sentence case for headings, buttons and labels.
- **Address:** buttons, tabs and menu items use the infinitive (Descargar CSV, Copiar enlace, Restablecer). Instructions use the impersonal or the formal imperative (Seleccione un municipio; Toque el mapa). No tuteo ("tú"), no "usted" pronoun. **One exception, by the project lead on 2026-11-16:** the Learn section is called "Aprende" (top bar, its tooltip, the page title and the map's link to it), as decision 106 (a) approved, not the infinitive "Aprender".
- **Punctuation:** open questions with ¿ and exclamations with ¡. Use the Spanish quotation marks only when needed (« »); otherwise straight quotes. A space before a unit (10 km, 25 %) is **not** used for percent in the observatory: write 25%.
- **Numbers and dates:** 1,234.5 (US form, as in Puerto Rico); dates "5 de octubre de 2026"; months in lowercase; 24-hour clock stays 24-hour ("07:15").
- **Units:** miles and feet stay the everyday unit for roads and sea level in Puerto Rico: millas (mi), pies (ft); metric stays m, km, km².
- **Acronyms:** keep the English acronym when the source is an English-language agency and add the Spanish name once: "FEMA (Agencia Federal para el Manejo de Emergencias)".
- **Inclusive wording:** use neutral nouns where one exists (las personas residentes) but do not force "@", "x" or "e" endings.
- **Do not translate word for word.** If the English is idiomatic, say it the way a Puerto Rican reader would. Keep the same length class where you can: Spanish runs about 20% longer, so check buttons and tabs.
- **Tabs have a width budget.** The eight tabs of the map panel sit in a grid of four columns (about 90 px each on a desktop screen, 71 px on a phone). In Spanish they are Resumen, Capas, Catálogo, Municipio, Posiciones, Transporte, Economía and Info; the longer
  "Clasificación" and "Acerca de" do not fit. The tabs show text only (the icons are hidden). Check the bar at 1280 px and at 360 px, in both languages,
  whenever a tab is added or renamed. A tab name that is cited in running text (for example "la pestaña Info") must be changed everywhere at once.
- **The top bar has a width budget too.** Spanish labels ("Preguntar", "Diccionario de datos") make the bar overflow between 1181 and about 1290 px, so in Spanish the view buttons stay icon-only up to 1320 px (English: 1180 px; the rule is at the end of the top bar block in `twin.css`).
  Check the top bar of all four pages at 1181, 1280 and 1321 px after changing a label.
- **The chat follows the same register.** Its own strings (`TX.es` in `js/chat.js`) use the formal imperative ("Pregunte", "Compárelo") and the same terms as the rest of the interface.

## Strings held for review

A Spanish string that needs a review before it is published (federal grant content: the WCRP layer and Table 10 of the housing page, HANDOFF decision 20) is held, not deleted. The set is what the strings belong to, not a word pattern. The line in `i18n_src/es/<scope>.json` repeats the English text, so the Spanish pages show English; `i18n_src/keep.json` lists the held strings that would otherwise warn; the translation stays in `i18n_src/held_for_review.json` (`spanish`, by scope). A held dictionary summary (the WCRP layer's entries and Table 10) is left out of `i18n_src/dictionary_plain.json` and kept under `dictionary_plain`, by entry id; to release it, move it back. The same file keeps the Spanish title of a dataset record (`titles`: the `es` title in `datasets.json` repeats the English one) and the headline figure that a domain had before it was set to null (`headlines`). `tests/test_held_for_review.py` fails when a held string shows Spanish or a held headline is back. The WCRP page (`wcrp.html`, branch `wcrp-area`) follows the same rule: its interface words are translated, and every sentence about WCRP, the vulnerability index, its method, results and errors is held (scope `wcrp`, the map's `labels_wcrp` and part of `econ_level`; `docs/wcrp.md`). To release one: put its Spanish back in the scope file, delete it from `held_for_review.json` and from `keep.json`, run `python i18n.py` and raise the `?v=` of `js/i18n.js` on the pages that use the scope. **Released on 2026-10-19** (the project lead's approval, HANDOFF decision 51): all of the WCRP Spanish (the page, the Social Capital map, the map's WCRP layer, the labels, the four dataset titles and the WCRP dictionary summaries), recorded in `released`; the plain-language rework of the page the same day (new and reworded strings, the "Updated 2020–2024" name of the second version) has its own `released` record. Still held: Table 10 of the housing page, the Public money headline and the federal money and FEMA summaries.

## What is not translated yet (and says so)

- **Data dictionary (phase 1, 2026-10, draft under review):** the summary of each entry is in Spanish from `i18n_src/dictionary_plain.json` and the glossary from `dictionary_src/glossary.json`; the names, how to read it, the short labels (units, geographies, group names, update frequencies), the source cards and the area and group descriptions are in Spanish from `dictionary_src/es/` (see its README: fingerprints keep the Spanish in step with the English, and stale Spanish falls back to English). Definitions, methods, cautions, source notes, codes, map-view labels and license text stay in English until phase 2; the page says so at the top. Held like the interface strings above, by what the text belongs to (`dictionary_src/es/held_for_review.json`): Table 10, the federal money and FEMA entries of Public money, the Public money area text, its labels, and the USAspending and OpenFEMA source cards (2026-10-21), and the 13 glossary terms marked `hold_es`. The WCRP entries' names and "how to read it" and the WCRP source card are released (decision 51). The Spanish is in files that only the Spanish page loads (`dictionary_list_es.json` after the page is ready, `dictionary_detail_<domain>_es.json` with an entry), so the English page loads what it did before.
- The series definitions shown outside the dictionary (Economy tab, chat) stay in English.
- Place names, business names, street names and the contents of data values are as the sources wrote them.
- Spanish drafted by Claude needs review by a native speaker before it is promoted as community-facing text.
