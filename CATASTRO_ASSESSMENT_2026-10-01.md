# Catastro Digital de Puerto Rico (CRIM) — integration assessment — 2026-10-01

## Access summary

Only one CRIM catastro service is usable anonymously and from a static site: Referencia/Limites_administrativos/MapServer (Barrios, Municipios, two cuadrícula grids). It answers direct REST calls without a token, supports query/pagination/outStatistics/groupBy, returns export images, and sends Access-Control-Allow-Origin for https://foundation-for-puerto-rico.github.io. Everything else in the catastro (Parcelario/Parcelas, Planimetria/Planimetria2017, Basemaps imagen 1998/2007/2010/2016-17, ProductosCartograficos, Hosted, Acuerdos, Operaciones) is token-gated (HTTP 200 body {"error":{"code":499,"message":"Token Required"}}). The two "public" portal items for Parcelas and Planimetría are Service Proxy items whose stored credentials fail server-side (code 500 CONT_0044 "Unable to generate token with the credentials provided with username: crimpr\cdpublisher"), regardless of User-Agent or Referer; that is the "empty JSON" seen earlier. CRIM's own viewer (cdprpc, Web AppBuilder 2.28) reaches Parcelas only through https://catastro.crimpr.net/proxy/proxy.ashx, which rejects requests without a Referer and injects stored credentials; its web map e564f0867187433eb8fbf0e59f901e28 is 403 anonymously. More decisive than the technical gate: the item licenseInfo for Parcelas and Planimetría states the service "solo puede ser consumido por medio de la aplicación Web de mapas del Catastro Digital", that download is prohibited except with CRIM authorization, and that making the data available "por medio de otros servicios, aplicaciones y portales manejados por terceros" is "estrictamente prohibido sin la debida autorización por escrito". The same boilerplate is attached to the Limites administrativos item, whose description nevertheless says "Este servicio es para uso público"; the repo already downloads and republishes those 902 barrios (cache/crim_barrios.geojson, site/data/barrios.geojson), which sits in that gray zone. Conclusion: parcels (and any parcel statistics, assessed values, exemptions, land-use codes) cannot be added without a written agreement with CRIM; the Barrios/Municipios reference layer can be used now, preferably as a live, no-storage overlay plus attribute-only enrichment, with the stored copy either authorized in writing or swapped for the public-domain Census equivalent (barrios are Census county subdivisions; CRIM's GEOID field is the Census COUSUB GEOID).

## Per-municipality statistics

Parcel statistics (parcel counts, land-use codes, exempt/taxable, assessed values) cannot be computed: every Parcelario endpoint answers {"error":{"code":499,"message":"Token Required"}} directly, the portal proxy items fail with 500 CONT_0044, and the item license restricts the service to CRIM's own viewer and forbids download and third-party redistribution without written authorization. What can be computed today, verified anonymously on the public Límites administrativos service (advancedQueryCapabilities.supportsStatistics true, supportsHavingClause, supportsDistinct, supportsCountDistinct, supportsPagination): (1) per municipality from Barrios layer 0: count of barrios and sum of CUERDAS via outStatistics=[{count GEOID as n_barrios},{sum CUERDAS as cuerdas}]&groupByFieldsForStatistics=MUNICIPIO (78 rows returned, HTTP 200); (2) per municipality from Municipios layer 1: MUNICODE, REGIONCRIM, REGIONCODE, CUERDAS, POB1970..POB2020 via a plain attribute query with returnGeometry=false (78 rows, 13.9 KB); (3) per CRIM region: municipality count and population via groupByFieldsForStatistics=REGIONCRIM (9 rows); (4) per barrio: the twin already derives assets, sfha, transit, lodging and assets_per_km2 by point-in-polygon in landuse.py:142-175 using the cached geometries, and km2 from CUERDAS * 0.003930. Population fields duplicate what the twin already takes from the Census (keep Census as the population source; use CRIM values only for cross-checking). All of these are reference attributes from the Junta de Planificación/Census, not tax-roll data, so they add context but not the property-tax indicators the task hoped for.

## Risks

- Terms: the license text on every CRIM map-service item forbids download and redistribution through third-party portals without written authorization; the twin already republishes 902 barrio polygons (site/data/barrios.geojson, built 2026-10-01 19:10; check whether it is deployed) under a meta.json license string that understates this. Either get authorization or switch the stored copy to Census county subdivisions.
- Parcels are not reachable anonymously (499 Token Required) and the only technical path (proxy.ashx with a spoofed Referer) violates CRIM's terms ('no puede obtener ... utilizando otros medios distintos a aquellos expresa e intencionalmente ofrecidos') and would stop working the moment CRIM tightens the proxy; do not build on it.
- PII: the Parcelas layer carries owner names and postal addresses; FPR's rule forbids surfacing them, so any future identify/popup must whitelist fields and the agreement should state that FPR will not display or store owner data.
- Availability: the Referencia service is a single ArcGIS Server 11.5 instance behind IIS with no tile cache; the live overlay depends on it, so keep it opt-in, zoom-gated at z13+, throttled, and give the user a fallback message when the export fails. The portal's own Service Proxy items have been broken (CONT_0044) at least since today's probe; CRIM may change URLs or permissions without notice (license: 'denegar o limitar accesos ... sin previa notificación').
- Load on CRIM: an export per pan from every visitor of a public site could be read as 'sobrecargar' under CMS/18.html; a build-time snapshot (if authorized) is friendlier than live calls; never issue island-wide queries at runtime (the full barrio GeoJSON is 7.3 MB per 500-feature page and took 2.4 s).
- Data lineage: CRIM's barrio and municipal polygons come from the Junta de Planificación; population fields stop at POB2020 and may diverge from the Census values the twin already uses; cuerdas are legal areas, not GIS areas, so area-based densities must say which one they use.
- Bilingual UI: the CRIM disclaimer is in Spanish with an English tail; attribution and the About tab should carry both since the twin's audience is bilingual.
- No open-data license exists for any CRIM dataset; even the 'free to download and distribute' wording applies only to the PDF maps in the Galería de Mapas, not to services.
